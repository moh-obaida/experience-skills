# Generic AI Layouts

## Recognize it
The same page skeleton regardless of product:
- Landing: sticky nav → big centered headline with gradient word → subhead → two buttons → product
  screenshot in a tilted frame → logo strip → 3 or 6 feature cards with icons → testimonial cards →
  pricing cards (middle one "Most popular") → FAQ accordion → CTA band → footer.
- App: sidebar + top bar + four stat cards + a line chart + a "Recent activity" table.
- Auth: centered card on a gradient or split-screen with abstract art.

## Why it happens
These are the statistically most common structures in training data and templates. They are
never *wrong enough* to be rejected, so they become defaults.

## Ask
- What does this product need to explain, prove, or let users do first?
- Would the structure change if the product changed? If not, it was not designed for this product.
- Which sections exist only because landing pages usually have them?

## Repair
- Derive structure from the story: problem → how it works → proof → action, in whatever form suits
  the product (a live demo, an interactive example, a long-form explanation, a single screen).
- Vary rhythm: not every section is a centered heading over a three-column grid.
- Cut sections that do no work (logo strips with no recognizable logos, generic testimonials).
- For apps, start from tasks and states, not from the sidebar-plus-cards template.
