# First Run

The first run is the empty state with the most at stake: a new user deciding whether the product
is worth their time.

## Goals

1. Reach a first meaningful success quickly (time-to-value).
2. Learn the core concept by doing, not by reading.
3. Avoid configuration that can wait.

## Patterns

- **Start from a template or example** relevant to what the user said they want.
- **Guided first creation:** the first create flow has helpful defaults and inline hints.
- **Sample content** clearly labeled and removable (useful in data and creation tools).
- **Import** existing work (files, other tools) when users arrive with content.
- **Progressive setup:** ask for integrations, teammates, and preferences when they become relevant.

## Onboarding checklists

A short checklist can orient users when setup has several real steps. Rules:

- Only real steps with real value.
- Progress persists; completed items collapse.
- It retires itself when done or can be dismissed.
- It does not dominate the operational home forever.

## Tours

Blocking product tours are usually skipped and forgotten. Prefer contextual hints at the moment a
feature becomes relevant. If a tour exists, keep it short, skippable, and replayable.

## Measuring

Count steps from sign-up to first meaningful outcome (see workflow-compression). The goal is to
remove steps, not to explain them better.
