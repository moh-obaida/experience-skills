# First-Use and Expert Burden

Products serve people at different points on the learning curve. Designs often favor one group
by accident.

## First-use burden

Signs:

- Long setup before any value (accounts, configuration, empty workspace)
- Blank starting states with no templates or examples
- Required concepts that must be understood before doing anything
- Mandatory tours that block the product

Repairs:

- Value before commitment where possible (try before sign-up, sample content)
- Smart defaults and templates
- Defer configuration until needed
- Teach in context at the moment of need, not upfront
- An empty state that leads to the first meaningful action

## Expert burden

Signs:

- Frequent users repeat beginner flows (wizards, confirmations, explanations)
- No shortcuts, bulk actions, or remembered settings
- Help text and illustrations taking space on every visit
- Onboarding checklists that never go away

Repairs:

- Shortcuts, bulk actions, presets, dense views
- Dismissible and self-retiring guidance
- Remembered configuration
- Direct entry and command palettes where warranted

## Balancing

The goal is a gentle ramp: a simple, obvious default path, with speed available as users grow.
When a change helps one group at the other's expense, name the tradeoff and prefer additions
(an expert path alongside) over replacements.
