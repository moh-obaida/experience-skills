# Observations: Tier A Depth Pass — 2026-09-25

This file records a focused research pass for five previously thin or unaddressed rows. It is
deliberately mixed-method: product documentation is marked `T`, while existing rendered
observations remain cited from their original dated files. The observations below are evidence for
transfer decisions, not claims that every cited product uses the named direction as a brand label.

## NeoBrutalism.com — community showcase (https://neobrutalism.com/showcase) — T, 2026-09-25
- NBR1 The showcase defines the shipped look with thick borders, hard shadows, loud color, and real production URLs, while explicitly separating community recognition from endorsement of each product decision.
- NBR2 The gallery is useful as style evidence but is not itself eight independent product precedents; do not count its screenshots as product interiors without inspecting the linked products.

## Gumroad — homepage (https://gumroad.com/) — T, 2026-09-25
- NBR3 The first task is explicit: “Start selling” sits beside Log in, while marketplace search is exposed as a separate input rather than hidden in decoration.
- NBR4 Decorative coins and illustrated feature scenes carry the personality; the selling action and marketplace search remain ordinary, high-contrast controls.
- NBR5 The page supports many creator categories and payment modes, so the loud environment is tied to experimentation and independent commerce rather than to every control.

## Framer — product and CMS surface (https://www.framer.com/) — T, 2026-09-25
- NBR6 Framer shows a real product interior with a canvas, CMS table fields, status values, navigation, and publishing actions; the product object remains more important than decorative treatment.
- NBR7 The adjacent lesson is structural: expressive surfaces can frame creation, but the table, fields, statuses, and publish action must retain conventional scan order.

## Headspace — app and content model (https://www.headspace.com/app) — T, 2026-09-25
- SFM1 Headspace describes a large library of guided meditations, sleep resources, expert-led programs, and personalized recommendations; a soft surface therefore needs a strong content taxonomy underneath the calm tone.
- SFM2 The product documentation emphasizes app access for personalization, progress tracking, and reminders; the calm environment is not a substitute for a persistent progress/state model.

## Calm — free content and sleep controls (https://support.calm.com/hc/en-us/articles/360044707294-What-Free-Content-is-Available-on-the-Calm-App) — T, 2026-09-25
- SFM3 Calm distinguishes free content from premium content with padlock cues and offers meditations, sleep content, soundscapes, a daily preview, and a breathing tool.
- SFM4 The soft direction must keep entitlement and state legible: a gentle surface still needs a clear locked/unlocked distinction and a direct route to a usable free action.

## Calm — sleep timer (https://support.calm.com/hc/en-us/articles/115002582908-How-to-Use-the-Calm-App-to-Fall-Asleep-Sleep-Timers-Playlists) — T, 2026-09-25
- SFM5 The sleep flow moves from playing content to a full player, then to a clock control and duration choice; softness is paired with explicit temporal state and battery guidance.

## Finch — home surface (https://help.finchcare.com/hc/en-us/articles/37780000231309-Exploring-the-Finch-Home-Page) — T, 2026-09-25
- SFM6 Finch makes daily goals, an available adventure, the pet, and a bottom navigation model coexist; character warmth is attached to progress mechanics, not used as a substitute for them.
- SFM7 The home surface has meaningful lifecycle gates: the adventure becomes available after the pet is energized, and chat becomes available after the adventure. A soft home must explain gated actions instead of presenting inactive decoration.

## Fabulous — routine model (https://help.thefabulous.co/en/support/solutions/articles/101000427430-how-does-fabulous-work-) — T, 2026-09-25
- SFM8 Fabulous uses morning/afternoon/evening routines, journeys, challenges, coaching, circles, and guided activities; the gentle tone is carried by a progression model with distinct time horizons.
- SFM9 A soft routine UI should make the next small action obvious and preserve the user's sequence. Large rounded cards without routine state would lose the reason the product feels calm.

## Apple Health — summary and trends (https://www.apple.com/health/) — T, 2026-09-25
- SFM10 Apple Health centralizes medications, sleep, activity, and other health information, then exposes trends and summaries; a calm visual language is compatible with dense data only when the summary hierarchy is explicit.
- SFM11 Privacy and secure access are part of the product promise, so health-oriented softness must communicate trust, provenance, and permissions rather than only pale color.

## Linear — project overview and detail sidebar (https://linear.app/docs/project-overview) — T, 2026-09-25
- MDE1 Linear keeps an overview tab, issues, documents, links, milestones, and a progress graph associated with one project object.
- MDE2 The project details sidebar can be opened from both the overview and issues pages; the list/detail relationship preserves the surrounding work instead of forcing a full navigation reset.

## Notion — database views and side peek (https://www.notion.com/en-gb/help/views-filters-and-sorts) — T, 2026-09-25
- MDE3 Notion lets the same database switch among table, board, timeline, calendar, list, gallery, and chart views; the list is a lens on shared objects, not a disposable page.
- MDE4 Side peek keeps the database interactive while a page is open; center peek and full-page are explicit alternatives when the item deserves more focus.

## Notion — database pages and preview (https://www.notion.com/en-gb/help/intro-to-databases) — T, 2026-09-25
- MDE5 Every database item is a page with properties, nested content, and a full-page escape hatch; the detail pane is not merely a preview card.
- MDE6 The list-to-detail relationship works because the selected item retains its object identity and the collection remains available for continued triage.

## Airtable — record-detail interface layout (https://support.airtable.com/articles/5805061650-airtable-interface-layout-record-detail) — T, 2026-09-25
- MDE7 Airtable offers sidesheet and full-screen record detail, with fields, permissions, collapsible groups, comments, revision history, and reusable layouts.
- MDE8 A detail surface should state whether a field is view-only or editable and whether a change affects the source record; visual proximity alone is not enough.

## Vercel — deployment overview and details (https://vercel.com/docs/deployments/overview) — T, 2026-09-25
- MDE9 Vercel separates the deployments collection from deployment details, then exposes Resources, build time, framework, logs, and errors inside the selected deployment.
- MDE10 The detail surface preserves the deployment's environment, commit, URL, and resource scope; a master-detail implementation should keep the selected record's authority visible.

## Cloudflare — custom dashboards (https://developers.cloudflare.com/analytics/custom-dashboards/) — T, 2026-09-25
- CMD1 Cloudflare custom dashboards apply a shared filter to every chart, then allow drill-down from an aggregate chart into Security Analytics or Log Search.
- CMD2 The live-control pattern is strongest when a dashboard has a declared scope, a current time range, and a path from anomaly to raw evidence.

## Cloudflare — DNS analytics (https://developers.cloudflare.com/dns/additional-options/analytics/) — T, 2026-09-25
- CMD3 Cloudflare's DNS analytics dashboard uses a defined set of panels, dimensions, filters, and time limits; the dashboard is an investigation surface rather than a collection of equal KPI cards.
- CMD4 Sampling and historical-data limits are part of the operational truth. A command center should expose freshness and precision boundaries when they affect decisions.

## Vercel — project overview and logs (https://vercel.com/docs/projects) — T, 2026-09-25
- CMD5 Vercel's project dashboard groups production and pre-production deployments, domains, settings, observability, and firewall management around a project scope.
- CMD6 Runtime logs, activity logs, and audit logs have different authorities and retention; a command center should not flatten them into one generic activity feed.

## Grafana — alerts overview dashboard (https://grafana.com/grafana/dashboards/4181-alerts-overview/) — T, 2026-09-25
- CMD7 Grafana's alerts overview distinguishes firing and pending alerts and severity counts, then presents the current alert collection; status is the focal object.
- CMD8 A live-control dashboard earns density when each panel changes the operator's next action. Decorative charts or equal tiles weaken the command-center contract.

## Sentry — developer quick reference (https://docs.sentry.io/pdfs/developer-quick-reference-guide.pdf) — T, 2026-09-25
- CMD9 Sentry's documented workflow connects issue alerts, metric alerts, filters, event details, and stack traces; an incident view needs a path from signal to code-level cause.
- CMD10 Alerting without an inspectable event, owner, or recovery path is notification chrome, not an operating surface.

## Scratch — about and editor model (https://scratch.mit.edu/help/about) — T, 2026-09-25
- PLY1 Scratch makes creation, sharing, remixing, and collaboration the product's playful loop; the playfulness is in the object being made and the community around it.
- PLY2 Scratch's editor is organized around a stage, sprite area, block palette, and script area. A playful creation surface still needs stable spatial roles.

## Finch — self-care tools (https://finchcare.com/about-finch) — T, 2026-09-25
- PLY3 Finch ties small goals to a pet's energy, adventures, reflections, breathing, and focus; the character is a feedback model, not only a mascot.
- PLY4 The playful tone remains useful when the task is emotionally difficult because the product keeps goals small and offers non-competitive progress paths.
