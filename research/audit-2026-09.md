# Repository Audit Before v0.2.0

Audit of v0.1.1 (commit 29a0280) on 2026-09-24, before the deep intelligence upgrade.

## Baseline numbers

| Measure | v0.1.1 |
|---|---|
| Tracked files | 306 |
| Generated (vendored) files | 107 |
| Skills | 12 |
| SKILL.md lines | 99–124 each (1,342 total) |
| Own reference files | 59 |
| Shared source modules | 27 (+2 script libraries) |
| Worked examples | 20 (all invented) |
| Real-world observations | about 20, in one catalog file |
| Tests | 43 (structure, scripts, 5 browser, routing fixtures, harness) |
| Scripts | 7 skill scripts, 8 repository scripts |

## What was strong and is kept

- Self-contained skills with shared source vendored and checked in CI.
- Mandatory "Start here" loading of the core, and checkpoints that change the agent's branch.
- Deterministic scripts tested in a real browser.
- The workflow, state, and interaction specialists' operational depth.
- The eval harness design (with/without, transcript parsing, blind judge).

## What was weak

- Almost no real-world precedent; examples were invented without saying so.
- No design-direction or composition library: anti-slop could detect defaults but not propose
  genuinely different alternatives.
- Typography and color guidance were brief; no palettes with verified contrast.
- The public-service example argued for one page over question pages without checking GOV.UK's
  research-backed guidance.
- Routing between skills was never observed in a real agent.
- No accessibility quick checks, content stress, rendered motion checks, or style inventory tools.
- Friction taxonomy lacked modes, interruptions, context switches, hidden status, and duplicates.
