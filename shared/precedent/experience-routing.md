# Precedent: Cross-Concern Product Surfaces

The observations below were observed on 2026-09-24 and are dated in the research log.

This module is for the architect when a surface crosses visual, workflow, state, and interaction
concerns. It is evidence for ordering specialists, not a reason to load every skill.

## `KH1`

Kahoot's join surface combines environment identity, a focused code input, a waiting state, and a
projector/mobile split. Route composition and visual identity before interaction polish, then state
and responsive verification. It is not evidence for decorating the code control.

## `GA1`

GitHub Actions combines dense composition, filters, state status, and recurring expert interaction.
Route information architecture and composition before control shortcuts; preserve status authority.

## `TV1`

TradingView combines a creation canvas, persistent chrome, expert controls, and delayed focal data.
Route workspace composition, interaction, state/loading, and responsive validation in that order.

## `UKD1`

GOV.UK question pages combine workflow, familiar controls, errors, and responsive constraints.
Route workflow and state before visual identity; the plain environment is an intentional product
decision, not a missing brand layer.

## `MD3`

MDN's live code example combines documentation composition, direct manipulation, and immediate
feedback. Route composition, interaction, and state; critical review checks whether the preview is
truthful and accessible.

## `LC1`

Linear's conceptual model is a precedent for routing from object confusion to information
architecture before surface decoration. Product-friction and workflow analysis precede visual work.

## `GF2`

Grafana's not-found surface combines state authority, recovery, identity, and a duplicated toast
that should be challenged. Route state first, then critical review and identity.

## `SD1`

Stripe's documentation choice surface demonstrates composition and interaction changing together;
route the content decision before styling the tabs.

## `ABm1`

Airbnb mobile demonstrates responsive composition, search context, and touch interaction. Route
responsive validation with interaction rather than treating the phone as a narrow desktop.

## `HN1`

Hacker News demonstrates that density, identity, and interaction can be one system. Route from the
product's scan task and audience rather than from a generic “minimal” direction.

## Routing rule

Use the smallest graph whose nodes own distinct decisions. A precedent can justify ordering only
when the target product shares its task, audience, frequency, and state conditions. After each node,
pass a compact artifact: what was decided, what evidence supports it, what remains risky, and what
the next node must not re-diagnose.
