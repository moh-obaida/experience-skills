# Precedent: Useful Density in Operational and Data Surfaces

Dense surfaces that stay scannable because every element is a real attribute of real work.
Observed 2026-09-24; IDs refer to `research/observations/`.

**How to use this file.** Use when a surface is OPERATIONAL, DATA-HEAVY, or LIVE CONTROL and someone
proposes "cleaning it up" by removing information, or when a sparse tool needs real density.

---

### GitHub — repository page
`GH1 GH2 GH3 GH4` · https://github.com/vercel-labs/skills · rendered
- **What works:** tabs with live counts; each file row shows its last commit message and age; one
  green primary action; reference metadata demoted to a sidebar.
- **Why:** every row answers "what changed here and when" without navigation.
- **Right when:** frequent, expert use on objects with change history.
- **Lesson:** density is useful when each column is a decision-relevant attribute.

### GitHub Actions — workflow runs
`GA1 GA2 GA3` · https://github.com/vercel-labs/skills/actions · rendered
- **What works:** status icon, commit title, workflow, branch, trigger, age, and duration per row;
  compact filters above; total count shown; frequent vs management items split in the sidebar.
- **Why:** triage of many runs needs status first and scannable attributes.
- **Lesson:** status-first rows plus filters beat KPI tiles for monitoring work.

### Hacker News — front page
`HN1` · https://news.ycombinator.com/ · rendered
- **What works:** ~30 items per viewport, two lines each.
- **Right when:** experts scanning headlines many times a day.
- **Does not transfer:** to touch-first or novice audiences without larger targets.

### Bloomberg — Markets ticker
`BL1` · https://www.bloomberg.com/markets · rendered
- **What works:** a persistent ticker strip of index values with colored changes under the masthead.
- **Why:** the most time-sensitive data becomes chrome that is always visible.
- **Caution:** color is paired with sign (▲/▼, +/−) so it does not rely on color alone.

### TradingView — chart workspace
`TV1 TV2 TV3` · https://www.tradingview.com/chart/ · rendered
- **What works:** canvas-first layout with tool rails on three sides and timeframe presets.
- **Why:** analysts need many tools one click away; the canvas stays central.
- **Trade-off:** icon-only toolbars are fast for experts and opaque for newcomers.

### Datadog — marketing depiction of dashboards
`DD1 DD2` · https://www.datadoghq.com/ · rendered
- **What works:** shows dense dashboards (numbers, host map, time series) as a selling point.
- **Lesson:** in monitoring, density *is* the capability; do not sparsify it to look calm.

### MDN — reference page
`MD1 MD2` · https://developer.mozilla.org/ · rendered
- **What works:** identical page anatomy across thousands of pages; support status answered first.
- **Lesson:** predictable structure is what makes dense reference usable.

### Coursera — discovery columns
`CO1 CO2` · https://www.coursera.org/ · rendered
- **What works:** three dense columns of courses with provider logo, type, and rating.
- **Lesson:** in discovery, a recognizable source mark is the fastest scanning cue.

### Steam — store navigation
`ST1 ST2` · https://store.steampowered.com/ · rendered
- **What works:** dense category navigation plus capsules with price and review summary.
- **Lesson:** capsules carry the two decision attributes (price, reviews) at a glance.

### Wikipedia — article
`WPd1` · https://en.wikipedia.org/wiki/Typography · rendered
- **What works:** very dense linked prose with consistent structure.
- **Lesson:** density of text is manageable with a stable reading structure and a clear title.

---

## Summary rules

1. Keep every column that answers a decision the user makes; remove the ones nobody reads.
2. Status first, then identity, then metadata, in each row.
3. Put filters and counts above dense lists; split frequent from management actions.
4. Density needs predictable structure and legible targets; check touch and zoom.
