# Authored System Application Examples

These are invented canonical examples, not observations of real products. They show how a system changes decisions on a particular route. Use them as regression prompts: build a sparse and dense state, then check whether the chosen system remains recognizable without a label.

| Surface | System and theme | Decision that changes the UI | Stress case and failure signal |
|---|---|---|---|
| Account page | Quiet Ledger / Ink-Bone | A dated activity list and pending-state summary replace empty metric cards; sign-out moves to low-prominence account utility | Zero transactions should show period and next action without a fixed-height void |
| Dashboard | Signal Foundry / Graphite Light | Live status, alert queue, and detail pane have distinct authority; timestamp makes staleness visible | At short laptop height the first alert and action remain visible |
| Learning platform | Lesson Trail / Olive-Cream | Current lesson and prerequisites form a navigable path; progress is textual, not a decorative streak | A learner with one completed lesson still sees what comes next |
| Commerce page | Object Gallery / Ivory-Charcoal | Image, variant, stock, price, and buy action share first useful viewport | A long variant name and out-of-stock selection do not hide alternatives |
| Admin interface | Measured Desk / Restrained Neutral | Priority work list precedes history; bulk actions appear only on selection | Hundreds of rows remain scannable and keyboard reachable |
| Editor | Studio Index / Cool Stone | User canvas owns space; tool rail and properties pane reveal current selection | Narrow viewport retains artifact and undo without two scroll traps |
| Mobile application | Precision Field / Stone-Signal | Current site, measurement, and offline save lead; map is optional detail | Mobile keyboard does not cover save or measurement units |
| Landing page | Edition House / Warm Editorial | Product story and clear conversion point alternate, rather than repeated feature cards | Long heading wraps without pushing the action below first useful viewport |
| Settings page | Civic Grid / Civic Ivory | One setting group at a time, clear consequences, visible saved/pending state | Error summary links to a field and does not erase input |
| Data-heavy tool | Dense Signal / Technical Dark | Tables, status, and exception lane share a stable grid; values and time are aligned | At 200% zoom, critical alerts remain navigable without horizontal page overflow |

A canonical example is useful only if its decision survives real data, accessibility, and responsive tests. Do not paste its wording or layout unchanged into a user's product.
