# Scenario: Audit a Product Experience Across Routes and States

## Scenario
An invented game product is being checked before a release. The HTML files are separate views for
visual coherence, UI necessity, composition, microcopy, state behavior, shared route patterns, and
acceptance. `clean.html` and marked controls in the views contain deliberate choices that should be
preserved.

## Prompt
Run a full product experience audit across the supplied views and states. Review visual coherence,
unnecessary UI, whole-screen composition, microcopy, state timing, cross-route drift, and rendered
acceptance as one product. Use the HTML names to identify the view being discussed. Render and
inspect relevant initial and changed states where the browser allows. Report only material findings,
with the observed evidence, user cost, likely owner, and a concrete correction or verification.
Include a no-change verdict for any deliberate treatment that holds up. Do not edit the files.

## Mode
review

## Current problem
The invented fixture set mixes real defects with legitimate asymmetry, dense expert information,
safety confirmation, intentional indicator treatment, and a page that needs no redesign. A broad
checklist can over-report or flatten the product if its findings are not tied to evidence and task.

## Expected skills
- use-all-skills
- visual-coherence-audit
- ui-necessity-audit
- composition-review
- microcopy-quality
- state-by-state-review
- cross-route-consistency
- screenshot-acceptance

## Key principles expected
- Find the concrete cut, stroke variance, clipped focus, or connector defect and distinguish it from the intentional single-edge treatment.
- Give doubtful labels, panels, separators, and choices an individual verdict while protecting safety, useful status, expert data, and recovery actions.
- Judge the whole screen against its main task; keep justified asymmetry and density.
- Correct misleading or vague wording without removing supported formats, constraints, or billing meaning.
- Check the trigger, correction, mutation completion, empty state, and healthy versus disconnected status.
- Trace shared pattern differences to their owning component and preserve route-specific composition.
- Tests and source do not establish rendered acceptance; state exact rendered coverage and limitations.

## Unacceptable recommendations
- Activate every specialist for a single isolated defect or present a roll call instead of findings.
- Redesign the restrained clean view, equalize justified asymmetry, or remove useful expert fields.
- Remove a safety confirmation, disconnected status, or recovery action because it looks redundant.
- Claim a defect is fixed or a route is accepted without exercising the relevant state and viewport.
