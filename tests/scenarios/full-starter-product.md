## Scenario
A runnable one-page service starter in `service.html` has generic filler, weak form semantics, no honest state model, and a brittle phone layout. The fictional product lets residents submit a repair request and track its status. The goal is a coherent, usable starter product, not a style gallery.

## Prompt
Use all Experience Skills to take `service.html` from this starter into a finished, coherent repair-request experience. Inspect and render the current page, decide what already works, compare three meaningfully different original design systems, choose one, simplify the request workflow, implement the page and useful states, then render, stress, inspect, critically challenge, repair, and verify it. Record what each of the fourteen sibling skills inspected, decided, changed or preserved, and verified. Do not merely list skill names. Keep the scope to this product and edit the actual file.
