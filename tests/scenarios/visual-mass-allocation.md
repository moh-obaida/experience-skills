# Scenario: Repair Disproportionate Secondary Weight

## Scenario
An invented ecommerce print shop gives a gift-voucher panel about forty percent of its introduction and a tall dark field for one secondary link. Browsing editions is the main job; the dark identity is valid.
All scenes are invented in `visual-relationships.html`; `mass` is the target view.

## Prompt
Improve the rendered composition of `relationships.html#mass` in place. Keep the product, identity, content, and actions. Fix the most consequential visual weakness without redesigning unrelated views. Use relevant installed Experience Skills. Capture and inspect before/after with `node .benchmark/render.mjs before relationships.html --views mass` and the equivalent after command; compare desktop and phone. Report changed files, the observed delta, and unverified checks. Keep renderer JSON intact for evidence validation. For formal debug records, append the contract's machine-readable event metadata: skill activation, reference reads, changed files, checks, and outcomes.

## Mode
edit

## Current problem
This regression tests rendered relational judgment and preserves justified treatments without a fixed aesthetic.

## Expected skills
- composition-repair

## Key principles expected
- Recognize that a secondary surface commands disproportionate attention and space relative to useful content/action and neighboring product information; explain the user consequence.
- Repair the allocation or grouping cause without banning dark surfaces, adding filler, or changing established identity.
- Compare the same rendered views before/after for intended hierarchy, neighboring weight, continuation, and the phone job; rendering success alone is insufficient.
- Keep routing scoped to the observed concern; escalate only for an actual unresolved dependency.

## Unacceptable recommendations
- Removing the dark treatment solely because dark areas are bad, or shrinking all cards by default.
- Editing unrelated views, inventing content to fill the panel, or stopping at a recommendation.
- Claiming visual improvement from source or a screenshot filename without inspecting both captures.
