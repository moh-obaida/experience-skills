# Scenario: Anonymous Reading and Save Journey

## Scenario
A content discovery product has a visually distinctive reader. Browsing is anonymous. A proposed
save redesign adds an email gate before the first save, while the source says nothing about identity
before saving. The save indicator differs between the reader, detail page, and persistent
navigation. One control says “Saved” while activating it removes the item. The mobile layout stacks
the panels but leaves the reading surface too small to use. A failed save message offers no retry,
and success has no useful continuation. A modal was proposed only to make the transition feel
dramatic.

## Prompt
Review this proposed save journey against the content discovery product's job. Keep the existing
visual identity in view. Browsing must remain anonymous; the source is silent about identity before
save. Give the few most consequential findings and a practical direction for each.

## Current problem
The polished visual concept can hide invented policy and broken continuity. A broad checklist could
bury the release-relevant journey problems, while a functionality-only review could flatten a
distinctive reader that otherwise serves the job well.

## Expected skills
- critical-review
- product-friction
- interaction-design
- state-design
- responsive-validation

## Key principles expected
- Identify the email gate as a product-policy decision, not a design requirement. Prefer a local,
  reversible save when technically and product-appropriate; identity can be offered later for sync
  or recovery. If the source explicitly required identity, preserve and design that requirement.
- Read, save, confirmation, and saved-collection surfaces should reflect one conceptual state.
  “Saved” must describe the current state and activating the control must communicate its outcome.
- A mobile stack is insufficient if it makes the reader unusable or hides the core action; protect
  the reading job and the user's place.
- A failed save should tell the user what remains true and how to retry or recover. A successful
  save should offer a relevant next step without forcing one.
- Reject the modal unless it serves an interaction need. Keep the established visual identity and
  expressive direction when they support the reading job.
- Rank policy, state/trust, and core-job failures ahead of polish. Do not turn the review into a
  full journey map or equal-severity checklist.

## Unacceptable recommendations
- Requiring an account because a profile or favorites screen looks better with one.
- Treating fewer clicks as an absolute rule or removing a source-required identity gate.
- Calling the mobile layout successful because all panels technically fit.
- Calling the interface confusing solely because it is visually expressive.
- Recommending the modal for drama without a user or product reason.
- Reporting a long list of minor polish issues before the primary journey defects.
